PROPOSITO
================================================================================

Este documento resume el codigo actual del CRM para que un agente pueda leer el
proyecto con direccion y reconstruir una V2 sin inventar el negocio.

No reemplaza la lectura del codigo fuente. Es un mapa de navegacion:
- que carpetas leer primero
- que modulos existen
- donde esta la logica mas riesgosa
- que patrones preservar
- que patrones corregir
- que archivos revisar antes de generar migraciones, services, controllers o UI

Uso recomendado junto a los 3 TXT:
1. prompt-reconstruccion-crm-v2.txt: vision, reglas y proceso.
2. contexto-codigo-crm-v2.txt: mapa del codigo Laravel actual.
3. contexto-db-crm-v2.txt: mapa de base de datos real y migraciones faltantes.

================================================================================
MODO DE LECTURA Y CONSTRUCCION POR FASES
================================================================================

Este contexto de codigo debe usarse por fases para no sobrecargar al agente.

Orden recomendado al leer:
1. Leer primero los 3 TXT de contexto.
2. Leer composer.json, package.json, routes/web.php y config principal.
3. Leer modelos del modulo piloto.
4. Leer controlador del modulo piloto.
5. Leer vistas del modulo piloto.
6. Leer migraciones/tablas relacionadas del modulo piloto.
7. Entregar plan de esa fase antes de tocar codigo.

Reglas:
- Una fase activa a la vez.
- Un modulo o flujo por fase.
- No mezclar refactor, DB, UI y formato masivo en el mismo lote.
- No tocar ventas/incentivos/reportes BI hasta validar primero un modulo piloto.
- Cada fase debe terminar con archivos modificados, comandos ejecutados y riesgos
  residuales.

Fases sugeridas desde el punto de vista del codigo:
1. Descubrimiento del modulo piloto.
2. Migraciones y modelo del modulo piloto.
3. Form Requests, Policies y permisos.
4. Service/Action y Controller delgado.
5. Vistas Blade/componentes/JS.
6. Tests Feature.
7. ETL piloto si el modulo tiene datos legacy.
8. Repetir patron por el siguiente modulo.

OBSERVACIONES PARA LA V2
1. ModuleHubController es buena practica que la V2 debe formalizar como
   Servicio con cache, permisos y validacion de items.
2. RecursosHumanosController repite el patron de ModuleHubController. En la
   V2 conviene un solo HubResolver con configuracion por archivo (modules/*.php)
   y sub-modulo opcional.
3. EntrevistaOnlineController ya usa verbos REST correctos (POST/PUT/DELETE):
   es el patron a seguir para todos los nuevos modulos. NO regresar a GET
   para mutaciones.
4. ExpireInactiveSession es el primer middleware de sesion estricto del
   proyecto. La V2 debe extenderlo (no reemplazarlo) y volverlo configurable.
5. centros_de_costo es una proyeccion de un sistema externo. En la V2 manejar
   con un Service de sync (LotobetClient/ContabilidadClient) y un Job de
   actualizacion. No CRUD libre.
6. La nueva navegacion por hubs implica que la V2 debe consolidar app.blade.php:
   menu lateral y hub deben compartir la misma fuente declarativa con permisos.
